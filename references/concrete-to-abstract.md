# Concrete to Abstract

## When to Consult

Use when the user could copy the current solution but might not recognize when to reuse it or when it would fail.

## Source Summary

The Institute of Education Sciences guide recommends connecting concrete and abstract representations of the same concept, assigning this recommendation moderate evidence. It also recommends alternating worked examples with learner problem solving. These are instructional recommendations across learning settings, not validation of conversational agents.

## Application to This Skill

- Start with a specific feature of the completed task and name the principle it illustrates.
- Give a nearby case and identify the shared structure explicitly. Similar surface details alone are insufficient.
- State a changed condition that would make the principle or chosen approach unsuitable. This three-part explanation is the skill's adaptation, not a prescribed sequence from the guide.

## Original Example

Fictional task: combine customer records using customer IDs.

> I matched records by customer ID because two customers can share a name. The general principle is to match entities using an identifier that is stable and unique within the data being combined. The same idea applies when matching products by product ID instead of product title. However, if two systems assign IDs independently, equal IDs may refer to different customers; use a verified mapping between systems instead.

The reusable cue is the need to establish identity across records. The boundary is whether both datasets share the same identifier system. This makes the explanation more useful than a universal rule to always match by ID.

## Limits

Showing a second case does not establish independent transfer. The guide includes learner practice that this skill does not require; its evidence rating must not be presented as an evidence rating for this skill.
